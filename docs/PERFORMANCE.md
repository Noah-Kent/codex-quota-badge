# 性能测量说明

## 已测环境

- 构建：`swift build -c release`；
- 设备：Apple Silicon；
- 系统：macOS 26.6.2；
- 数据：`CODEX_QUOTA_PREVIEW=1` 固定假数据，不读取真实会话日志；
- 应用空闲约 50 秒后，使用 `ps` 采样两次，间隔 10 秒。

| 指标 | 第一次 | 第二次 |
| --- | ---: | ---: |
| CPU | 0.0% | 0.0% |
| RSS | 56,160 KiB（约 56.8 MiB） | 56,160 KiB（约 56.8 MiB） |

这只说明在上述环境中，显示假数据时的短时间空闲占用；它不应被解读为所有 macOS 版本、硬件或使用状态下的保证。

## 磁盘边界

macOS 的 `fs_usage` 按调用追踪文件系统活动时要求 root 权限。为了避免要求用户授予额外权限，本项目没有进行该项直接采样，也不在 README 中把“零读取”或“零磁盘影响”当成实测事实。

可验证的实现与测试边界是：

- 首次启动才完整定位最新有效日志；
- 缓存当前日志路径、修改时间和最近有效快照；
- 每分钟只检查已追踪文件的状态；
- 未变化时直接复用内存快照；
- 文件变化时只解析该文件；
- 删除或新会话事件才触发重新定位；
- 不写入 Codex 文件、数据库或配额历史。

测试执行器覆盖“未变化复用缓存”“文件变化只解析追踪文件”和“目录变化重新扫描”这三种刷新决策。运行：

```bash
swift run CodexQuotaBadgeTestRunner
```

## 后续测量

正式发布前，建议在经过 Apple 公证的 Release 版本上，分别在 Apple Silicon 和 Intel Mac 上记录：启动峰值、五分钟空闲 CPU/RSS、日志变化后的刷新延迟，以及经用户明确同意后获得的文件系统追踪数据。
